# 308 段落「智能解读」接口契约（Codex → WorkBuddy）

时间：2026-09-29 ｜ 归属：前端 UI = WorkBuddy；后端接口已实现（`/api/analyze_segment`），待部署。

## 一、需求（308 + 308b，修正：划选触发）

生成结果页（作品说明书正文）支持**划选 / 选中段落 → 自动弹出「智能解读」**，点击后用通俗语言解读选中文本（提炼要点 / 解释术语 / 提示对评分维度的支撑）。**不是固定按钮，是划选触发。**

**308b 硬约束**：对外文案**规避「AI」字样**，按钮名用「**智能解读**」（备选「通俗讲解」），不得出现「AI 分析」。后端接口名保留 `/api/analyze_segment` 没关系（代码内部，前端看不到）。

## 二、后端接口（已实现）

### POST /api/analyze_segment
请求（JSON）：
```json
{ "text": "这里是该段落/章节的正文原文" }
```
- `text` 必填；超 3000 字自动截断。
- 前端把**当前段落/章节的正文文本**直接传上来即可（无需 history_id / 章节 key，v1 从简）。

响应成功：
```json
{ "success": true, "analysis": "2~4 句通俗解读……", "source": "llm" }
```
响应失败（缺正文）：
```json
{ "success": false, "error": "缺少需要解读的正文段落" }   // HTTP 400
```
响应失败（演示只读态）：
```json
{ "success": false, "error": "演示账号不接入外部模型，登录后可深度解读", "error_code": "demo_readonly" }   // HTTP 403
```
响应失败（额度用尽 / LLM 异常）：
```json
{ "success": false, "error": "……友好文案", "error_code": "..." }   // HTTP 500
```

## 三、前端要做的（WorkBuddy）

1. **划选触发**：正文里 `mouseup`/`touchend` 后用 `window.getSelection().toString()` 取选中文本，非空则在选区附近弹出「智能解读」浮动操作（图标 + 文字，风格统一精致，与现有导出球/回顶同视觉体系）。
2. 点击浮动操作 → 展开**分析气泡**：先 loading 态，`POST /api/analyze_segment {text}`（text = 选中文本）成功后在气泡里显示 `analysis`，可点击空白处/关闭按钮收起。
3. **失败优雅降级**：`success:false` 时把 `error` 直接展示（如「登录后可深度解读」），不影响正文展示、不弹堆栈。
4. **loading 可中断 / 重复点击防抖**：同一时间只发一个请求，别连点爆并发。
5. **演示只读态**：接口会返 403 的友好文案，前端照常显示即可，无需额外隐藏浮动操作。

## 四、验收标准

1. 双端结果页划选文本后能弹出「智能解读」浮动操作。
2. 点击出分析（通俗易懂、2~4 句），可收起。
3. 演示态/额度不足有友好提示，不报错崩溃。
4. 全站不出现「AI 分析」字样，统一用「智能解读」。

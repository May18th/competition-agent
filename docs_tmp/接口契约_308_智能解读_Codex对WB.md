# 308 段落/图表「智能解读」接口契约（Codex → WorkBuddy）

时间：2026-09-29 ｜ 归属：前端 UI = WorkBuddy；后端接口已实现（`/api/analyze_segment`），待部署。

## 一、需求（308 + 308b + 308c + 308d）

结果页「智能解读」覆盖**全部内容**，触发方式分两类：

1. **文本（正文各章节 / 答辩路演讲稿）**：划选 / 长按选中某段 → 松开 → 在选区附近**自动弹出**「智能解读」（无需点按钮，无选中不出现）。
2. **可视化图表（评分雷达图 / 柱状图 / 对比图等）**：图表**不可划选**，改为**点按 / 悬停图表区**弹出「智能解读」。

**解读质量（用户强调「一定要智能全面」）**：讲人话、提炼要点、解释术语、关联评分维度、图表说人话；**禁止敷衍套话 / 通用模板**，必须结合当前内容具体展开。短标签 / 评分数字不做解读。

**308b 硬约束**：对外文案**规避「AI」字样**，按钮名用「**智能解读**」（备选「通俗讲解」），不得出现「AI 分析」。后端接口名保留 `/api/analyze_segment` 没关系（代码内部，前端看不到）。

## 二、后端接口（已实现）

### POST /api/analyze_segment
请求（JSON）：
```json
{ "text": "这里是段落/章节正文原文，或图表的标题+关键数据描述", "kind": "text" }
```
- `text` 必填；超 3000 字自动截断。
- `kind`：`text`（默认，正文段落）或 `chart`（图表标题 + 数据）。图表由前端把标题 + 关键数据拼成一段描述文本传 `text`，`kind=chart`。
- 前端把选中文本 / 图表描述直接传上来即可（无需 history_id / 章节 key，v1 从简）。

响应成功：
```json
{ "success": true, "analysis": "通俗深度解读……", "source": "llm", "kind": "text" }
```
响应失败（缺内容）：
```json
{ "success": false, "error": "缺少需要解读的内容" }   // HTTP 400
```
响应失败（演示只读态）：
```json
{ "success": false, "error": "演示账号不接入外部模型，登录后可深度解读", "error_code": "demo_readonly" }   // HTTP 403
```
响应失败（额度用尽 / LLM 异常）：
```json
{ "success": false, "error": "……友好文案", "error_code": "..." }   // HTTP 500
```

## 三、前端要做的（WorkBuddy）

1. **文本·划选触发**：正文里 `mouseup`/`touchend`（移动端长按选中）后用 `window.getSelection().toString()` 取选中文本，非空则在选区附近弹出「智能解读」浮动操作（图标 + 文字，风格统一精致，与现有导出球/回顶同视觉体系）。无选中不出现。
2. **图表·点按/悬停触发**：图表区（雷达图/柱状图/对比图等）绑 `click`/`hover`，把图表标题 + 关键数据拼成描述文本，`POST /api/analyze_segment {text, kind:"chart"}` 弹「智能解读」。
3. 点击浮动操作 → 展开**分析气泡**：先 loading 态，成功后在气泡里显示 `analysis`，可点击空白处/关闭按钮收起。
4. **失败优雅降级**：`success:false` 时把 `error` 直接展示（如「登录后可深度解读」），不影响正文展示、不弹堆栈。
5. **loading 可中断 / 重复点击防抖**：同一时间只发一个请求，别连点爆并发。
6. **演示只读态**：接口会返 403 的友好文案，前端照常显示即可，无需额外隐藏浮动操作。

## 四、验收标准

1. 双端结果页划选文本后能弹出「智能解读」浮动操作；点按/悬停图表也能弹出。
2. 解读通俗易懂、结合具体内容（非套话模板），可收起。
3. 演示态/额度不足有友好提示，不报错崩溃。
4. 全站不出现「AI 分析」字样，统一用「智能解读」。

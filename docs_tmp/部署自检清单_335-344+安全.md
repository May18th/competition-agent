用途：豆包验收。后端已部署前提：服务器已换 app.py / export_demo_samples.py + demo_sample.json / demo_sample2.json / static/demo_sample.json，并已 restart。

## 一、安全修复（5 处越权/泄露，curl 验证）

### 1. /api/demo 不再返回用户历史
```
curl -s "http://127.0.0.1:8080/api/demo?history_id=1"
curl -s "http://127.0.0.1:8080/api/auto_generate"
```
✅ 都只返回预置 demo 样例（data.proposal 是「垃圾分类桶/助老终端」这类学生项目），不再返回任意 history_id 的用户内容；无样例时返回「暂无演示样例」。

### 2. 分享链接只能建自己的记录
```
# 用 A 的 cookie 给「不属于 A」的 history_id 建分享，应 404/无权
curl -s -X POST "http://127.0.0.1:8080/api/share/999999" -H "Content-Type: application/json" -H "Cookie: comp_uid=<A的cookie>"
```
✅ 返回「记录不存在或无权分享」（不再能给别人记录建分享链接）。

### 3. 导出回源只能取本人记录
```
curl -s -X POST "http://127.0.0.1:8080/api/export_word" -H "Content-Type: application/json" -d '{"history_id":999999,"mode":"fast"}' -H "Cookie: comp_uid=<A的cookie>"
```
✅ 不会把 999999 的他人内容导出（回源取不到即走空/降级，不越权读）。

### 4/5. 评分回写只写本人历史（越权写封堵）
```
# 带别人 history_id 提交「评分 X 星」→ 不应覆盖他人 rating
curl -s -X POST "http://127.0.0.1:8080/api/feedback" -H "Content-Type: application/json" -d '{"content":"评分5星（很好）","history_id":999999}' -H "Cookie: comp_uid=<A的cookie>"
```
✅ 提交成功但他人 history.rating 不变（UPDATE 带 AND user_id 校验，匹配不到就不改）。

### 6. 分享 token 熵加固
```
curl -s -X POST "http://127.0.0.1:8080/api/share/<本人history_id>" -H "Cookie: comp_uid=<A的cookie>"
```
✅ 返回的 token 约 22 字符（token_urlsafe(16)=128bit），不再是 ~11 字符（64bit）。

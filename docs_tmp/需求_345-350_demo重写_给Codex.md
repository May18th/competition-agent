## 二、要求①：demo 数据必须是学生参赛项目本体

1. **正文只写项目本身**：项目背景与痛点、需求分析与目标用户、技术方案与系统架构（指**项目**的架构，不是网站的架构）、关键硬件/成本结构、竞品对比、实测数据与效果、数据口径说明、应用前景与商业模式、团队分工与知识产权、下一步计划。
2. **项目必须是真实学生做得出来的**：如校园智能取件柜、宿舍楼智能分类桶、乡村小学科学教育盒子、独居老人跌倒监测装置、县域中学志愿填报辅助等。禁止把「一个网站/平台/赛事系统」本身当成参赛项目。
3. **允许虚构，但内部必须自洽**：
   - 每个数字都要能自洽推导，并在文中写明口径，例如「按本校 2 栋宿舍楼 4 个投放点、2025 年 9 月 15 日—10 月 5 日共 21 天实测统计」「抽检 512 次，人工开袋复核」。
   - 百分比、样本量、金额之间要能对上（如 642/1,046 = 61.4%、BOM 分项之和 = 单桶物料 268 元、收入 - 成本 = 毛利）。
   - **严禁**出现「→ 替换为真实数据」「待补」「示例值，需按实际核实」「TODO」「占位」这类开发者备忘。
4. **口径标注要用项目口吻**：未实测的一律标注为「测算值 / 计划值 / 目标值 / 参考值」，这是给评委看的诚实声明，不是给开发看的待办。写成「已标注项：…按参考值口径处理」而不是「待补项：…需按实际核实」。
5. **平台名不得出现**：产品名「创科智绘 / 科创智绘」一律不出现；如确需提及平台，只能用网站正式名「科创赛事助手」，且只允许出现在页脚/免责区的一句话里，不得进入正文。

## 三、要求②：后端生成 prompt 必须加硬禁令（待 Codex 落地）

请在所有生成「作品正文 / 申报书 / PPT 大纲 / 答辩稿 / 评委反馈」的 prompt 中，加入以下硬禁令段落（建议作为系统级约束，优先级高于其他指令）：

```
【硬禁令 · 作品正文输出规范】
1. 输出内容只能是「用户参赛项目本体」的正文，禁止描述本网站/平台/工具自身的功能、架构、使用方法、定价、生成流程。
2. 正文中禁止出现下列任何字样（含其变体与近义表述）：
   评审引擎、多智能体、智能体、双盲、流式输出、LangGraph、豆包、Flask、WorkBuddy、
   PPT模板、知识库、大模型、去AI味、创科智绘、科创智绘、B/S、AI、11套、15套、
   以及任何形如「功能说明」「使用说明」「核心作用」的小节标题。
3. 禁止输出开发者备忘：不得出现「待替换」「→ 替换为…」「待补」「TODO」「占位」
   「示例值，需按实际核实」等字样，也不得写「提交前需替换为实测」这类提示。
4. 所有数字必须自洽且标注口径（实测值 / 基线值 / 测算值 / 计划值 / 目标值）。
   未实测的只能标注为测算值或计划值，不得冒充实测。
5. 如需提及本平台，只能使用正式名「科创赛事助手」，且仅限页脚或免责声明一句。
```

**后处理侧建议同步加一道机器校验**（生成结果返回前，或离线巡检时执行）：

- 命中上面第 2、3 条任一关键字 → 直接判为不合格，触发重新生成或拦截，不要原样返回给用户。
- 命中「## 待替换数据清单」「## 功能说明」「## 使用说明」这类章节标题 → 同上。
- 建议实现一个可复用的 `check_content_clean(text)` 函数，返回命中项列表，并在日志里记录。

## 任务二【P0·流程】孪生站独立化部署（staging 与主站完全隔离）

**背景**：当前 staging 与主站共用同一个后端（127.0.0.1:8080）和数据——这违反"新功能不在源站测试"的隔离要求。必须把 staging 改成**独立副本**。

**执行**：
1. **复制代码**：`cp -r /opt/comp-agent /opt/comp-agent-twin`（排除 .git 和 .venv，或独立复制后清理）
2. **独立数据**：确认 /opt/comp-agent-twin 下的数据文件（data/、demo_sample.json、用户数据、日志）独立存在，staging 的读写一律落在 twin 目录，**绝不写主站数据**
3. **独立后端**：为 twin 启动独立 gunicorn（端口 **8081**，独立进程），如：
   ```
   cd /opt/comp-agent-twin && gunicorn wsgi:app --bind 127.0.0.1:8081 --workers 2 --threads 8
   ```
4. **改隧道指向**：编辑 /root/.cloudflared/config.yml，把 staging 的 ingress 从 `http://127.0.0.1:8080` 改为 `http://127.0.0.1:8081`，重启 cloudflared
5. **验证独立运行**：
   - `curl -s -o /dev/null -w '%{http_code}\n' -H "Host: staging.kechuang2026.cn" http://127.0.0.1:8081/api/health` 应 200
   - 浏览器访问 https://staging.kechuang2026.cn/ 应正常加载且与主站一致
   - **数据隔离验证**：在 staging 上执行一次生成/保存操作，确认主站数据文件未被修改（对比主站数据文件 md5 前后不变）
6. **主站不动**：整个过程中 /opt/comp-agent 主站进程（8080）不重启、不修改、不停服

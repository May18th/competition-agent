一、项目背景
1.1 立项背景与赛事规模
 大学生科创赛事的规模与参与度持续攀升。据教育部、人民日报等公开口径，中国
国际大学生创新大赛（2025）已覆盖 161 个国家和地区、5673 所学校、619
万个项目、2443 万人次参赛，总决赛入围 4720
个项目。每年数以百万计的团队要独立完成"读懂评分标准 → 撰写申报书 → 打磨格式
→ 准备答辩"的高门槛工作。
1.2 真实的参赛困境
 前期调研中反复听到学生反馈（脱敏后归纳）：写申报书写了一周仍不清楚评委要
什么；做 PPT 反复调格式耗时大于内容本身；不同比赛模板与评分标准各异，一份材
料改了又改。困境本质不是"学生不努力"，而是"评审逻辑没有被工具化"。
1.3 作品定位
 本作品把"读懂评分标准 → 检测撞题风险 → 生成/优化申报书 → 模拟评委打分 →
输出答辩材料"固化为可复用的多智能体流水线。用户只需提交"赛事名称 +
项目创意（可附草稿）"，系统自动走完全链路，产出可下载编辑的 Word / ZIP
材料包。与"通用 AI 写作助手"的核心差异是：按具体比赛官方评分标准生成 +
多智能体协作 + 图表/PPT 联动。
1.4 首批内置赛事
 内置 iCAN、互联网+、挑战杯、国家级大创等赛事评分标准知识库，生成时按所
选赛事自动匹配对应规则与章节要求。
二、痛点分析

2
2.1 学生侧痛点
  标准黑箱：评分标准分散在各官网通知，学生难把"创新性 30% / 商业性 25% /
技术性 25% / 团队性 20%"四项权重逐项落到稿子每一节。
 格式黑洞：大量时间花在排版、字号、目录、匿名脱敏，而非内容。
 复用困难：A 赛写的材料到 B 赛因口径不同几乎重写。
 撞题焦虑：担心创意与往届项目撞车却无从比对。
2.2 教师侧痛点
 指导教师常带多支队伍，难逐字批改；更缺一个帮学生"按标准自检、提前发现短
板"的辅助工具。
2.3 现有竞品不足（公开评价，已标注来源）
  秘塔写作猫：免费版仅体验，正常需开会员（24/48 元每月两档）；Safari
兼容性差；定位偏校对/润色，非全流程。
 讯飞写作：App 极简、缺比赛差异化模板；公开评测称其大模型会输出未经核实数
据（幻觉风险）。
2.4 竞品缺口（本作品切入处）
 现有工具多是"通用写作助手"，缺"按比赛评分标准生成 + 多智能体协作 +
图表/PPT 联动"的完整链路。
三、需求分析
3.1 功能性需求
 标准对齐（按所选赛事官方权重逐项展开）、全流程覆盖（解析→检测→生成→评
审→答辩）、差异化输出（简洁版/深度版 + Markdown/Word
导出）、可复用可演进（赛事知识库沉淀，新增赛事只补库不改码）。
3.2 非功能性需求
 性能（深度版单任务通常数分钟，具体随模型负载波动，见版本差异表）、并发（
生成任务并行上限 3、大模型调用并发闸 16，超出排队）、安全（匿名隔离/密码哈希/
双盲脱敏/上传不入库）、可用（前端零框架、依赖本地化、断网可演示）。
3.3 差异化需求
 同一团队不同阶段诉求不同：初赛"先看看效果"要快轻的简洁版；冲刺正式提交要
成稿级深度版。

七、技术方案
7.1 总体架构（五层）
 自上而下：①接入层（浏览器前端，五个 Tab，经 120 余条 REST
路由与后端交互）；②服务层（Flask
应用，承载页面、生成入口、历史、上传解析、导出）；③编排层（LangGraph
状态图，双工作流）；④模型层（DeepSeek-Chat 主模型，Claude/GPT
适配器预留）；⑤数据层（SQLite 历史库、本地赛事知识库、上传/导出暂存）。
7.2 多智能体编排（节点与状态，来自代码核查）
 核心是有状态的 LangGraph 状态图，所有节点读写同一份
CompetitionState（TypedDict，共 40 个字段：输入 10、中间结果 27、控制 3）。
"节点读写同一份状态、不直接传参"是能无条件增删节点、也能做条件回边的前提。系
统有两套工作流：
  简洁版工作流（12 个节点）：rule_parser、similarity_checker、idea_evaluator
、one_liner、analysis、writer、judge、proposal_analysis、defense、ppt、sp
eech、revise。
 深度版工作流（19 个节点）：在简洁版基础上新增 competitor、business、risk
、tech、plan、social、expert_review，并复用其余节点——即深度版比简洁版
多出"竞品/商业/风险/技术/实施/社会价值/专家复审"等环节。

八、作品功能逐一说明
8.1 赛事知识库
 将 iCAN、互联网+、挑战杯等赛事的评分标准、章节要求、常见扣分点蒸馏为结
构化文本知识库；生成时按所选赛事自动匹配，拿不准的权重以"当年官方通知为准"兜
底。
8.2 规则解析 Agent（rule_parser）
 职责：读取赛事规则与创意，提取评分维度与权重。输入：赛事名、创意草稿、规
则文本。输出：结构化评分点清单，供后续撰写逐项对齐。
8.3 同质化检测 Agent（similarity_checker）
 职责：将用户创意与知识库往届方向做相似度比对，预警撞题风险。价值：把"创
意撞车"这一隐性风险前置暴露。
8.4 文稿生成 Agent（writer）
 职责：按规则解析结果分章节撰写申报书。机制：每个智能体只干一件事，能按官
方评分标准逐项展开。

8
8.5 评委评审 Agent（judge）
 职责：以官方评分标准做加权模拟打分，给出扣分点与改进建议。定位：AI
自查，非真实评分，用于赛前预判短板。
8.6 答辩与展示准备（defense / ppt / speech）
 深度版额外产出答辩预测问题、PPT
大纲、演讲稿，形成"申报—评审—答辩"完整闭环。
8.7 导出中心
 支持申报书、答辩问题、PPT 大纲、演讲稿、竞品分析、商业计划单项导出与一键
ZIP 打包，以 Word 为主便于二次编辑。
九、产品特点与 AI 功能核心作用
9.1 产品特点
  赛事专精：按具体比赛官方评分标准生成，而非通用写作。
 多智能体闭环：写 → 模拟评委 → 定向修订被挑章节，比单次 prompt 完整可控。
 可信内容：反编造 + 数据来源标注，编了会被发现。
 双盲合规：生成与导出自动脱敏，符合 iCAN 等匿名要求。
 双档区分：简洁版快速出稿、深度版成稿级，覆盖不同诉求。
 轻量可演示：前端零框架、依赖本地化，断网也能做基础演示。
 轻量协作：匿名 uid + 一键同步码，跨设备不依赖重账号体系。

创新赛道官方口径（青岛理工大学 2026 iCAN 选拔通知，与多校一致；注意 2026
部分校赛出现过"创新性 35/实用性
25"新口径，引用分值以当年官方总决赛通知为准）：
9.3 风险前置
 同质化检测在撰写前暴露撞题风险，把问题消灭在成稿前。
9.4 闭环评审
 "撰写 → 模拟评委 → 定向修订"形成闭环，比单次生成更可控。

9
9.5 反编造与数据标注
 三层机制：① prompt 硬规则禁止"已合作/已落地"断言；②
代码层兜底把漏网"已合作"降级为"计划"；③ 每个数字标来源（实测值/行业公开数据/
测算值/设计目标值），拿不准标"测算"并生成待替换清单。诚实声明：不保证 100%
不编，但保证"编了会标出来、能被发现"。
9.6 双盲脱敏
 对双盲赛事自动隐去院校、指导老师、单位；即使生成漏了，导出层也递归剔除身
份信息。
9.7 技术难点与创新点
 难点在"生成得对"：① 多智能体编排按标准逐项展开、能自检返工（深度版 19
节点、共享 40 字段状态）；② 反编造 + 数据标注让内容可信；③ 多赛事规则蒸馏与
自动匹配。三点组合才是"能交的申报书工具"，而非"能出字的玩具"。

## 新增章 A｜核心创新点（建议插在原「九、产品特点与 AI 功能核心作用」之后）

本项目不是「又一个通用 AI 写作工具」，而是**把赛事评分标准翻译成可执行的生成约束，并让评委视角提前介入生成过程**。三处创新如下：

**A1 架构创新：不是单轮直出，而是「生成—评审—定向修订」的闭环**

不是让模型一次写完就交付，而是把规则解析、文稿生成、模拟评委、定向修订拆成可独立评测的节点，形成闭环。模拟评委按当前赛事的评分维度先行打分并指出具体章节的缺失，再由修订节点针对被点名的章节定点修补，而不是整篇推翻重写。这一闭环把「写完了才知道哪里不行」变成「写的过程中就知道哪里不行」。

**A2 知识库创新：不是通用语料，而是按赛事结构化的评分口径库**

不是把往届范文塞进检索库让模型模仿（那既涉及版权，也会导致撞车），而是按「赛事—赛道—评分维度」三层结构化沉淀官方规则与评分口径，让生成过程直接受规则约束。知识库只存规则与口径，不存参赛作品原文，从机制上规避版权与同质化风险。

**A3 功能体系创新：不是只出文稿，而是一次成型且互相引用**

不是单独生成一份申报书，而是把申报书、答辩问题、PPT 大纲、演讲稿、图表数据在同一套素材上生成，彼此引用同一组数字与结论。这解决了团队分开准备材料时最常见的「PPT 里的数字和申报书对不上」问题。

## 新增章 C｜风险分析与应对（插在新增章 B 之后）

**C1 技术风险**

- **依赖第三方大模型 API**：模型服务价格波动或接口变更会直接影响生成成本与稳定性。
  应对：模型调用层做统一封装，支持更换底层模型而不改动上层流水线；关键路径设置超时与降级，单次节点失败不阻断整体出稿。
- **AI 幻觉无法完全消除**：生成内容仍可能包含未经核实的数字或表述。
  应对：在数据层面强制标注来源类型（实测值 / 公开数据 / 测算值 / 设计目标值），禁止裸数字；同时提供「待替换数据清单」，把估算项集中列出提示人工复核。**本系统定位为辅助工具，最终提交内容须经团队人工复核**——这是本项目的明确边界，而非缺陷回避。
- **赛事知识库持续更新压力**：赛事规则每年调整，知识库滞后会导致生成内容偏离当年口径。
  应对：知识库按赛事分文件维护，规则变更时只更新对应文件；每次更新后跑一轮规则解析回归检查。

**C2 市场风险**

- **通用大模型入局**：若通用模型上线科创备赛插件，会分流部分浅层需求。
  应对：本项目的壁垒不在「会不会写」，而在「懂不懂评分口径」——赛事结构化知识库与模拟评委闭环需要逐赛事积累，通用插件短期难以覆盖多赛事差异化规则。
- **高校预算周期性波动**：B 端采购集中在特定时段，收入存在季节性。
  应对：C 端小额付费与 B 端机构授权并行，降低单一收入来源依赖。

**C3 运营风险**

- **用户增长与转化**：免费用户转化为付费用户的比例存在不确定性。
  应对：简洁版保留为免费入口承担引流，深度版承载付费；按首年渗透率分档做保守/中性两版预测（见商业模式章）。
- **并发与额度成本**：高峰期调用量上升会推高成本。
  应对：已设置并发上限与全局额度闸门（Semaphore 并发控制 + 全局额度配额），团队规模扩大时可提升额度或改为每人自带密钥。

**C4 内容合规风险**

- **用户上传涉密项目**：参赛项目可能含未公开技术细节。
  应对：用户数据隔离存储，不用于模型训练，提供本地删除入口。
- **生成内容版权**：生成物可能与其他选手表述相近。
  应对：内置同质化检测节点，在撰写前比对知识库往届方向并预警撞题，把问题消灭在成稿前。
- **AI 生成内容参赛伦理**：赛事对 AI 辅助的边界规定尚不统一。
  应对：产品明确定位为「辅助备赛工具」，输出物保留用户可追溯的修改痕迹，并提示用户遵守当届赛事的原创性规定。

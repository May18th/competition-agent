- 主站 P0（手机端打不开）已闭环：根因是域名 kechuang2026.cn 未 ICP 备案，阿里云拦截直连大陆源站；已切回 Cloudflare Tunnel 保底。
- 用户确认孪生站方案：所有新功能先在 staging.kechuang2026.cn 测试，测通后再替换主站。
- 上一份指令（A 记录 + 8.149.236.90 + DNS only 直连）**已被否决**：直连源站会被备案拦截（80 返回备案拦截页、443 RST），与主域名直连失败同根因。

## 任务：搭建 staging 孪生站（走 Tunnel，不直连）

### 第1步（服务器配置，WorkBuddy/Codex 执行）
编辑 /root/.cloudflared/config.yml，在 ingress 中「www.kechuang2026.cn」之后、fallback（service: http_status:404）之前，增加一条：
```
  - hostname: staging.kechuang2026.cn
    service: http://127.0.0.1:8080
```
保存后重载 cloudflared：
```
cloudflared tunnel ingress validate
systemctl restart cloudflared   # 或 kill 旧进程后重启，取决于部署方式
```
验证 tunnel 新配置生效：
```
cloudflared tunnel list   # 确认 409b6f55-... 连接正常
curl -s -o /dev/null -w '%{http_code}\n' -H "Host: staging.kechuang2026.cn" http://127.0.0.1:8080/api/health   # 应 200
```

### 第2步（Cloudflare DNS，用户手动操作）
Cloudflare 控制台 → kechuang2026.cn → DNS → Records → Add record：
- Type：**CNAME**（不要用 A）
- Name：staging
- Target：**409b6f55-93c1-44fc-a077-a6c53de7831b.cfargotunnel.com**
- Proxy status：**已代理（橙色云朵）**（不要灰云，灰云=直连会被备案拦）
- TTL：Auto
- Save

### 第3步（验收）
1. dig +short staging.kechuang2026.cn @1.1.1.1 → 应返回 CF IP（104.21.63.156 或 172.67.147.62），**不能**是 8.149.236.90
2. curl https://staging.kechuang2026.cn/api/health → 应 200 且返回 status ok
3. 浏览器打开 https://staging.kechuang2026.cn/ 应正常加载页面
4. 双端（桌面+手机）各验一次，附截图

## 注意事项
- 不要用 A 记录直连 8.149.236.90——必被备案拦截。
- staging 与主站共用同一个 Tunnel（409b6f55-...）和同一份代码目录 /opt/comp-agent/（如需隔离目录，另行说明，本轮先共用）。

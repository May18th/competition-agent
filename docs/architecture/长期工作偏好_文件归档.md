# 长期工作偏好：按功能归档

以后每个项目开始时先建立清晰的目录边界，再开始写代码或生成产物。默认采用以下规则：

- `frontend/`：页面、样式、浏览器端脚本与静态资源。
- `backend/`：服务入口、业务逻辑、智能体、导出器、知识库与运行期数据。
- `docs/`：架构、接口、赛事资料、评委验收、交接和模板，按子目录归类。
- `tests/`：可重复测试、探针和测试说明；测试输出放 `artifacts/qa/`，不散落源码目录。
- `artifacts/`：演示、参考样例、研究快照和质量检查产物，按用途分目录。
- `logs/`：运行日志、错误日志和调试记录；日志不和源码混放。
- 根目录只保留 README、全局协议、版本控制配置和必要启动入口。

整理时遵守两条优先级：

1. 先保证运行路径不变。数据库、上传目录、生成目录、临时导出目录和知识库的位置由启动入口明确维护，移动前必须同步代码并做启动/导出回归。
2. 先按属性归档，再清理重复或临时文件。不可确认来源、版权或用途的文件放入归档区，不直接删除；密码、令牌和个人凭据不写入仓库或长期记忆。

这条规则是项目协作默认约定，后续新项目沿用，不需要每次重新提醒。

# 隐私与安全说明（科创赛事助手）

> 用途：答辩备查 + 对用户/评委说明。诚实为底线，不吹"银行级加密"。

## 一、已做到的隐私保护

1. **匿名隔离**：每个访客一个匿名 `comp_uid`，历史记录 / 反馈按它隔离，访客之间互不可见。
2. **uid 防伪造**：cookie 用 HMAC 签名（itsdangerous + `.uid_secret`），不能伪造成别人的 uid。
3. **密码哈希**：登录账号的密码只存 PBKDF2 哈希，不存明文。
4. **双盲脱敏**：双盲赛事（如 iCAN）自动隐去院校 / 指导老师 / 单位；导出层递归剔除身份证、负责人姓名、院校、学院等身份信息。
5. **上传材料不共享**：上传的申报书草稿只用于本次生成，不入共享知识库；不收集他人获奖原文（版权整改）。
6. **反编造 + 数据标注**：不编造事实，每个数字标来源（实测 / 行业公开 / 测算 / 设计目标），拿不准明说"测算"。
7. **HTTPS + 敏感路径拦截**：有 SSL 证书；nginx 把 `/.env`、`/.git`、`/build` 改成 404，防配置和源码泄露。
8. **限流按 uid 不按 IP**：避免校园网 NAT 全校共用一个出口误伤正常用户。

## 二、边界 / 不足（诚实声明）

1. **匿名方案是"防君子"不是强认证**：谁拿到你的 uid 就能看你的历史，签名只防"伪造"、不防"盗用"。
2. **同步码 = 历史钥匙**：一键同步码是"谁拿到码谁看历史"，码泄露历史就泄露，属轻量同步的固有代价。
3. **历史数据明文存 SQLite**：做了脱敏，但拿到服务器文件仍可读，未做存储层加密。
4. **暂无隐私政策 / 删除机制**：数据不会被用于训练，但目前没有显式告知用户存多久、怎么删。
5. **默认无登录**：赛前默认匿名，跨设备靠同步码；账号体系是可选增强。

## 三、答辩话术（对应技术答辩 Q7）

> "我们做了匿名隔离、HMAC 签名防伪造、密码哈希、双盲脱敏、上传材料不入共享库，而且不用用户数据做训练。需要诚实说明的是：匿名方案是轻量隔离，不是强认证——它适合校园比赛这种低敏感场景，真要上高敏感场景，我们会换账号体系 + 存储加密。我们不夸大，也不回避。"

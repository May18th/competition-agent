# 待办 · WorkBuddy：移动端体验问题与一键定位建议

> 这些都在 `index.html`（你专属），我只做问题归集和可能的定位方向，不直接改前端。
> 后端接口我先自查过：`/api/history` 返回 200、`/api/health` 返回 200，上传接口逻辑未变，说明「看不到历史」「上传失败」主要是前端/浏览器兼容，不是后端挂了。

## 一、按浏览器归集

### ① 微信内置浏览器

- 无法上传文件，只能选照片和文字（`<input type=file>` 的 `accept` 在微信里容易只剩图库/相机，建议放宽 accept、给「从聊天记录选文件」的引导，或改用微信 JS-SDK）。
- 无法查看历史记录（历史列表在微信里可能没渲染/滚动失效）。
- 申报书上传失败（可能微信拿不到真实文件名或 MIME，`secure_filename` 后文件名异常；或文件选择器根本没选到 docx/pdf）。
- 不稳定、卡顿；简洁版/深度版有时生成不出内容（若接口实际返回 error，前端要把 error 明确弹出来，别让用户以为没反应）。
- 快速查看生成内容时页面卡顿、内容缺失（大段 `marked.parse` 全量重渲染 + 长列表 DOM 太重，移动端内存吃紧；建议按板块懒渲染/只渲染当前 tab，别一次性把整份 HTML 都挂上）。
- 生成较慢（深度版本来约 2 分钟；简洁版经 tier 修复后应更快，但移动端网络/轮询间隔也会放大体感）。
- 无法查看下载内容（微信内置浏览器对 `blob:` 下载支持差，建议微信场景改 `window.open` 直链，或提示复制链接到系统浏览器打开）。

### ② 百度浏览器

- 三步指引不稳定：点第一步后，有时只弹第二步、不再弹第三步（指引状态机没把「已点击→下一步」和「自动下一步」区分好，或计时器被移动端节流）。
- 进入第二步后界面上下颜色分层、显示不稳定（很可能是 coach 高亮蒙层 + 背景渐变在移动端视口高度计算错位）。

### ③ QQ 浏览器

- 指引只有第一步，后面两步不出现。

### ④ 夸克浏览器

- 指引同上（只有第一步）。
- 有界面颜色分层。
- 有空白卡顿，但不影响使用。

## 二、个人喜好建议（用户提出）

做一个「一键返回/板块快速定位」：生成内容很多，看完一个板块想看下一个要来回翻很久。建议两种二选一或都做：

1. 右下角悬浮「回顶部」按钮（滚到一定距离才显示）；
2. 结果区顶部做横向锚点条（概览/诊断/评审/图表/答辩…），点击平滑滚到对应板块。

## 三、可配合后端（不急，需要再叫我）

- 若要把「生成失败」做得更明确：`/api/status/<task_id>` 已经会返回 `status/error/detail`，前端只需在 error 分支把 `detail` 弹出来，不用改后端。
- 若想缩短生成时间：深度版耗时长主要在 LLM 串行链路，真要优化是后端的活（比如并行化部分节点、缩短 selfcheck），但会动到质量和流式，建议先不动。

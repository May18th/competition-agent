## 一、重要更正：414 不是「完全没做」，402 轮已经做过一整轮

我一开始 grep `contrast` 无命中，判定 414 未做——**这是误判**（和 413、412 同一个坑：只看关键词）。
实际 `style.css` 第 21-40 行有注释完整的「402 轮 · 全局对比度规范」：

- 日间/夜间两套 token 都按**最坏有效底色**反推（注释明写：卡片会叠 2~3 层 surface，
  只按 `--bg-0` 算会掉到 3.4~4.2:1，所以逐个按最坏底色加深到 ≥4.9:1）
- 已补齐日间漏 override 的 `--info` / `--info-strong` / `--ok`
- 已修 CSS 变量在 `:root` 完成置换、导致 `body.light` 改不动的陷阱
- `.modal h2` 白字也已在 `body.light` 下覆盖成 `#1f2a44`

**所以 414 的正确范围是「补 402 轮的遗留」，不是重做全局。** 请 Codex / 豆包不要再从头改一遍，
否则会和 402 那套精心校准的值打架。

## 二、我怎么找的：写扫描器实测，而不是凭感觉改

写了 `scan_contrast414.py`（只读，不改文件）：解析 `static/*.css` 每条规则块，
取 `color` 与 `background`，按 WCAG 2.1 相对亮度公式算对比度，列不达标项。

**踩的两个坑（已修，写在脚本注释里）**：
1. 第一版把 `linear-gradient()` / `var(--x)` 当背景却解析不了 → 退回白底，
   于是「白字 + 渐变深底」被误报成 1.00:1，噪声完全盖住真问题。
2. rgba 半透明背景没跟页面底色混合 → 深蓝字 + 8% 透明蓝算出 1.30:1 的假阳性。
修法：渐变/变量背景标记 UNKNOWN 并排到列表最后；rgba 背景先与底色混合再比。

真正的问题只出现在**日间（body.light，白底）**。逐条核实 `body.light` 覆盖后：

不改 `style.css` 是为了避免和 402 轮那套校准值冲突，只做增量覆盖，接线到 index.html（第 35 行）。

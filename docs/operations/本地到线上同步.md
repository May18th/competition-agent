# 本地到线上同步

## 当前结论

`D:\competition-agent` 是唯一开发工作区。修改本地文件不会自动改变
`https://kechuang2026.cn/`。

截至 2026-10-02 的只读核验结果：

- 线上首页仍引用旧版 `app.js` / `style.css`，与本地字节内容不一致。
- 线上 `GET /api/memory` 返回 `404`；本地后端已有该路由。
- 本地 `main` 与 `origin/main` 已分叉，且工作区有未提交改动；禁止直接
  `git pull`、`git reset --hard` 或强推覆盖远程历史。

## 同步边界

需要发布：

- `frontend/index.html` 和 `frontend/static/` 静态资源；
- `backend/app.py`、`backend/competition_agents.py` 及其实际导入的生成/导出模块；
- 与运行入口匹配的 `backend/wsgi.py`、依赖和官方资料索引。

不允许从本地覆盖：

- `backend/competition.db`（线上用户历史、反馈和记忆）；
- `backend/uploads/`、`backend/generated/`、`backend/tmp_export/`；
- `.env`、`.uid_secret`、管理员凭据和任何密钥。

## 标准发布流程

1. 在本地完成语法、前端语法、导出和双端回归。
2. 生成发布文件清单并核对 SHA-256；只传清单内文件。
3. 在服务器先备份代码和 SQLite，再传文件。
4. 使用 `safe_restart.sh` 等待正在生成的任务结束后平滑重载服务；找不到该脚本时默认拒绝裸重启，只有确认没有运行中任务并显式设置 `WB_ALLOW_UNSAFE_RESTART=1` 才能降级。
5. 发布后逐项验证首页、`/api/health`、`/api/memory`、登录/后台、生成、历史和三类导出。
6. 任一项失败，恢复代码备份并再次验证；数据库备份只用于数据灾难恢复，不随代码回滚。

项目内的 `backend/scripts/deploy_safe.sh` 实现了备份、同步、重启、校验和回滚骨架。
执行前必须根据服务器当前入口确认远端目录布局，并显式传入文件清单；不要使用
脚本默认通配符把运行期目录或数据库带上。

## 连接不可用时

连接不到服务器时无需反复输入上传命令，也不要自行执行破坏性的 Git 命令。
只需要恢复可用的 SSH 部署通道；通道恢复后再执行上述流程。若必须由人工触发，
应运行项目脚本而不是手工 `scp` 覆盖文件，并把脚本输出的备份路径、校验结果和
失败原因保留下来。

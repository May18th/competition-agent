### 419 轮（P0 最高优先 · 手机打不开修复 + 孪生站同步——Codex 处理，服务器与域名权限在你）
**事故**：用户手机 4G 实测：夸克白屏、手机自带浏览器白屏、豆包加载不出、微信加载不出（4 张截图实锤，03:16-03:18）。但服务器进程正常（gunicorn 活着、health ok、index 200、负载 0.12、内存磁盘充足），公网 curl 也 200。
**根因（实锤）**：DNS 解析显示 kechuang2026.cn 走 **Cloudflare 代理**（104.21.63.156 / 172.67.147.62），且**源站无 443 证书**（nginx 无 ssl 配置、/etc/ssl 无正式证书）——HTTPS 完全依赖 Cloudflare 边缘。国内手机网络访问 CF 节点不稳定/被干扰 → 全端打不开；桌面端能开是因为本机网络连 CF 节点恰好可用。
**修复方案（推荐直连源站，最稳）**：
1. 源站安装 Let's Encrypt 证书：`apt install -y certbot python3-certbot-nginx && certbot --nginx -d kechuang2026.cn`（HTTP-01 验证走 80 端口，源站 80 → gunicorn 8080 已正常）；
2. nginx 自动配好 443 后 `nginx -t && systemctl reload nginx`；
3. **DNS 控制台把 kechuang2026.cn 从「代理（橙云 Proxied）」改为「仅 DNS（灰云 DNS only）」**，解析直指源站 IP 8.149.236.90——国内手机直连阿里云节点，不再绕 CF；TTL 设 60 秒尽快生效；
4. 改完验证：`curl https://kechuang2026.cn/api/health` 应 200，且 `curl -k -v https://kechuang2026.cn/ 2>&1 | grep 'subject:'` 显示证书是源站 Let's Encrypt（不再是 CF 边缘证书）；
5. 手机 4G 关 wifi 实测夸克+自带浏览器+微信，截图回执。
**并行 · 孪生站同步代码（用户 406 轮方案：新功能一律先在孪生站测，测好再替换正式站）**：
- 在源站建孪生站目录（如 /opt/comp-agent-twin/），把 /opt/comp-agent/ 当前代码同步过去（rsync 排除 data/、logs/ 运行态文件）；
- 孪生站独立端口/子域（如 nginx server_name twin.kechuang2026.cn 或 8.149.236.90:8081），同样配 443 证书；
- 后续所有新功能先部署到孪生站，豆包在孪生站双端实测通过后，再同步到正式站；正式站 30 号前保持稳定不折腾。

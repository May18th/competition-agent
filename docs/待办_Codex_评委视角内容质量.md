## 1. 模拟评审：三个专家分数太接近、评语雷同 → 一看就是同一个人写的

现状：三位专家给分普遍落在 88-92，评语结构一致（先夸创新性、再提"建议补充数据"）。

要求：
- **分数必须拉开**：让三个专家分别扮演「技术专家 / 投资（商业）评委 / 落地应用评委」，
  给分区间刻意错开（比如技术 78-85、投资 82-90、落地 70-80），并允许出现 60-70 的低分。
- **评语必须带具体缺陷**，不能只说"建议补充数据"。要说清"第几章的哪个结论缺少什么证据"。
- **专家之间要有分歧**：同一件事一个说"技术门槛高"，另一个说"工程化难度被低估了"，
  这种分歧反而真实。
- 输出结构建议：`{专家角色, 打分, 最认可的一点, 最致命的一点, 要求补充的证据}`。

## 2. 答辩问题太泛：换成"针对这个项目"的尖锐问题

现状：问的是"你的项目创新点是什么""市场前景如何"这类放之四海皆准的问题。

要求：**必须先读申报书正文，再出题**。问题要逼到具体数字和具体环节上，例如：
- 硬件类：续航多久？充一次电用几天？测了几台样机、跑了多长工况？
- 算法类：样本量多少？误报率多少？在哪个数据集上测的？基线是什么？
- 成本类：BOM 成本多少？量产后能降到多少？定价依据是什么？
- 竞品类：大厂如果三个月做同样的事，你怎么办？（用户特别点名这一条）

建议：每题附一句「参考答案要点」，否则学生答不上来，工具价值打折。

## 3. 图表数字是编的 → 评委一问"这数据哪来的"就露馅

现状：预算饼图、市场规模柱图、进度甘特的数字都由 LLM 自由发挥，
我们却在图上写得像真数据。

要求（三选一，我倾向 A）：
- **A（推荐）**：图表每个数据点必须带来源标注，来源只有三种合法值：
  ①团队输入（引用用户在创意/申报书里写的数字）②公开数据（必须写明机构+年份）
  ③测算假设（明确标"测算：基于 XX 假设"）。编不出来源的数字一律不许上图。
- **B**：图表默认生成"待填写"版本 —— 数值留空/给量级提示，让团队填真实数。
- **C**：图下方固定一行小字"图中数值为示例，需按团队实际数据替换"。

另外：图表 caption 里加来源行，导出 Word/PDF 时要带出来（我这边已经能把图插进 Word）。

## 4. "已生成 10000 字"不是卖点，是注水

现状：结果区/导出都在强调字数，评委的反感点是"字多≠质量"。

要求：把产出指标从「字数」换成「可交付度」，例如：
- 有数据支撑的论点数量
- 占位/待补充项数量（越少越好）
- 覆盖的评分维度占比
前端我这边已经不主推字数了，后端如果还在往 `completeness` / summary 里塞"共 X 字"，建议一并换掉。

## 5. 申报书里出现的引用不能是编的

现状：偶尔会出现"据《XX 报告 2026》显示…"这类看起来很真、其实没有出处的话。

要求：prompt 里明令禁止编造具体机构+年份的数据引用；
需要行业数据时，要么用团队提供的，要么写成"行业普遍认为/公开数据显示"这类不含出处的表述，
要么留 `【需补充数据来源】` 标记（前端已有占位符扫描机制会统计数量）。

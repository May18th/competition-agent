# 科创赛事助手 · 错误经验蒸馏库

> 用途：本项目（及同类 Flask + 云服务器 + 域名 + 前端联调）踩过的坑，蒸馏为「现象 → 根因 → 解法 → 预防」。
> 下次遇到类似错误，先查本库再动手。按类别检索。

---

## 一、部署与服务器

### 1. PythonAnywhere 上传后打不开（404 / 空页）
- 现象：zip 上传到 /home/May18th，访问 may18th.pythonanywhere.com 无内容。
- 根因：Web 入口（WSGI 文件）没有指向 Flask 应用；依赖（flask 等）未装到虚拟环境；路径写错。
- 解法：Files 页面找到 wsgi.py 编辑，改成 import 你的 app；Console 里 `pip install -r requirements.txt`（要看到输出/光标，别以为"没反应"）；代码路径必须和 wsgi 里写的一致。
- 预防：上传后第一步检查 wsgi.py 的 import 路径；pip 装依赖用 `--user` 或先 `python -m venv`。

### 2. `unzip` 命令没反应 / 找不到
- 现象：控制台输入 unzip 没输出。
- 根因：命令打错或根本没执行（焦点没在控制台）；Linux 上未安装 unzip。
- 解法：先 `ls` 确认文件在；`sudo apt install unzip` 或改用 `python -m zipfile -e 包.zip 目标目录`。
- 预防：远程控制台先 echo/回车确认会话活着再跑命令。

### 3. 阿里云 ECS 上用错本地命令
- 现象：在服务器 SSH 里粘贴 `cd "C:\Users\..."`、`git add` 本地路径 → `No such file or directory`、`not a git repository`。
- 根因：把本地 Windows 命令当成服务器命令执行；服务器代码目录是 /opt/comp-agent，本地是 C:\...\科创赛事助手。
- 解法：服务器上用 Linux 路径；本地改动先 `git commit/push`，服务器 `cd /opt/comp-agent && git pull`。
- 预防：分清"本地操作"和"服务器操作"两条通道；服务器代码以 /opt/comp-agent 为准。

### 4. 域名打不开：证书文件不存在
- 现象：`ls: cannot access '/etc/nginx/kcwx.online.*'`；443 不监听。
- 根因：证书 .pem/.key 没上传到 /etc/nginx/，nginx 配置引用了不存在的文件。
- 解法：`cp /root/kcwx.online.pem /etc/nginx/`（文件要先上传到服务器），再 `nginx -t && systemctl reload nginx`，`ss -tulnp | grep 443` 验证监听。
- 预防：改 nginx 前先 `ls` 确认引用的证书/路径存在；`nginx -t` 每次必跑。

### 5. SSL handshake failed: bad key share
- 现象：nginx 日志大量 `SSL_do_handshake() failed (SSL: error:0A00006C ... bad key share)`；部分客户端（老设备/某些运营商）打不开。
- 根因：TLS 1.3 的 X25519 key share 问题 / 客户端与服务器 TLS 版本不兼容（旧手机、QQ 内置浏览器）。
- 解法：server 块加 `ssl_protocols TLSv1.2 TLSv1.3;` 并 reload；仍不行再排查 DNS 与运营商拦截。
- 预防：https 站点配置里显式声明 ssl_protocols；用 curl -k -I https://localhost 自测。

### 6. 域名解析问题（.online 被拦截 / DNS 未生效）
- 现象：电脑/手机/QQ 都打不开，但手机流量可以；用 IP（http://<SERVER_IP>/）可以。
- 根因：域名 DNS 解析在部分网络（尤其某些运营商/浏览器安全拦截）不通；.online 后缀信任度低。
- 解法：换 .cn 域名（kechuang2026.cn）后正常；旧域名 kcwx.online 弃用。
- 预防：国内访问优先 .cn；解析记录要 A 记录（主机记录 @ 和 www，记录值服务器公网 IP）；换域名是最后手段。

### 7. nginx 站点文件不在预期位置
- 现象：`/etc/nginx/sites-available/default` 改了半天不生效，或者生效配置在别处。
- 根因：站点配置实际在 `/etc/nginx/sites-available/comp-agent`（或被 include 的其他文件）。
- 解法：`nginx -T 2>&1 | grep -E 'listen|ssl_certificate'` 找真实生效配置；`cat /etc/nginx/sites-available/comp-agent`。
- 预防：改 nginx 前先 `nginx -T` 看实际加载了哪些配置。

### 8. gunicorn 只监听 127.0.0.1:8080
- 现象：`ss -tulnp` 只见 `127.0.0.1:8080 gunicorn`，公网访问 8080 不通。
- 根因：gunicorn 绑定了内网回环地址，公网流量必须经 nginx 反代（8080 本来就不该直接暴露）。
- 解法：nginx 里 `proxy_pass http://127.0.0.1:8080;` 即可，公网只开 80/443。
- 预防：Flask/gunicorn 一律绑 127.0.0.1，公网入口只留 nginx。

### 9. 服务器磁盘/内存问题（2核2G）
- 现象：并发生成时卡顿、OOM。
- 根因：2G 内存跑多 Agent + LLM 调用吃紧。
- 解法：控制并发；必要时升级配置或加 swap。
- 预防：大任务错峰；监控 `free -m`。

## 二、开发与代码（前后端）

### 10. Flask 改了不生效
- 现象：改 app.py / competition_agents.py 后，线上 /api/status 还是旧结构（没有 stage_label / pct）。
- 根因：run.py 是 `debug=False`，不会热重载；gunicorn 没重启。
- 解法：改完代码必须重启服务（systemctl restart 或 kill gunicorn 再起）。
- 预防：每次改后端 → 重启 → 再验证接口，三步固定。

### 11. 打包 zip 缺 PPT 和图表
- 现象：POST /api/export_zip 返回的 zip 里只有 10 个 Word，缺 12_路演PPT.pptx 和 11_项目数据图表.docx，但菜单标着"已含 PPT"。
- 根因：从历史记录打开结果页时 `_lastData.rich_deck/rich_charts/rich_tables` 为空（富媒体未随历史恢复），后端空数据跳过 PPT/图表生成。
- 解法：历史恢复时同步恢复富媒体数据；或导出时检测缺失并提示重新生成。
- 预防：历史持久化要连富媒体一起存；导出前校验数据完整性。

### 12. 档位承诺与实际不符
- 现象：默认档位 fast（勾选简洁版），实际跑了 9 Agent 全流程 + 7774 字 + 页面显示"深度版预计4~5分钟"。
- 根因：前端默认勾选与后端实际执行档位不一致；卡片文案（50秒出1000字）与真实行为脱节。
- 解法：统一档位判断逻辑；文案与实测对齐（简洁约40秒/深度约4~5分钟）。
- 预防：任何"承诺时间/字数"都要以实测为准，前后端共用一份常量。

### 13. 评分/档位标签不一致
- 现象：结果页显示"简洁快速版 76 分"，历史记录里同一记录显示"深度版 86 分"。
- 根因：前后端字段语义不一致，历史记录覆盖了当前展示值。
- 解法：统一字段名（档位、评分）与取值来源；历史记录不覆盖结果页实时数据。
- 预防：同一条数据的字段口径全局唯一。

### 14. 404 返回裸 JSON
- 现象：访问不存在路径返回原始 JSON 错误，无友好页面。
- 根因：Flask 默认 404 handler 未定制。
- 解法：加全局 404/500 页面（HTML 或前端路由）。
- 预防：上线前扫一遍异常路径。

### 15. /api/health 只探进程存活
- 现象：上游 LLM API 挂了，健康检查仍显示"服务正常"。
- 根因：health 只 check 进程，不 check 依赖。
- 解法：健康检查可选加依赖探测（LLM key 可达性/数据库连接）。
- 预防：健康检查口径按"服务可用"而非"进程存在"设计。

### 16. 简洁版"套话"问题
- 现象：简洁版生成内容偏套话、空泛。
- 根因：prompt 无具体场景约束。
- 解法：prompt 改"短而实 + 每段三要素（场景/数字/技术名词）+ 低分自动补写"。
- 预防：简洁版 prompt 定期用真实输出回炉。

### 17. 富媒体/图表中文变方框
- 现象：生成的 chart PNG 中文显示为方框。
- 根因：服务器缺中文字体（matplotlib 默认字体不含中文）。
- 解法：安装中文字体（如 Noto Sans CJK / 文泉驿），matplotlib 指定 font.sans-serif。
- 预防：服务器初始化就装中文字体。

## 三、工具与环境（本机 Windows）

### 18. Bash 不可用
- 现象：Bash 工具报"Windows host，用 PowerShell"。
- 根因：宿主机是 Windows，shell 通道只有 PowerShell。
- 解法：所有命令行用 PowerShell 语法（Get-ChildItem、$env:、反斜杠路径）。
- 预防：本机操作默认 PowerShell。

### 19. ffmpeg 不存在
- 现象：where ffmpeg 无结果。
- 根因：未安装。
- 解法：`python -m pip install imageio-ffmpeg`，用 `imageio_ffmpeg.get_ffmpeg_exe()` 拿二进制路径。
- 预防：装一次即可复用；合成视频用该二进制。

### 20. bu 视口固定窄屏（481x529）
- 现象：browser_use 截图是 481x529 竖条，录演示视频太窄。
- 根因：bu 视口固定，无法设宽屏。
- 解法：录宽屏用 cu 全屏截图（1920x1080），页面操作仍用 bu，截图用 cu。
- 预防：涉及录屏/宽屏素材时直接用 cu 截全屏。

### 21. AI 生成图转 .ico 的坑（重要）
- 现象：AI 生成的图标转 ico 后：细线糊、白底非纯白（~254,254,254）键控留灰边、深色满幅方块突兀、前后台同图标无辨识度，反复被否。
- 根因：AI 图是位图 + 渐变背景 + 细线，小尺寸必然劣化；白底键控阈值不对留灰边。
- 解法（最终采用）：**放弃 AI 图转 ico，用 PIL 程序化绘制矢量级图标**——圆角卡片（rounded_rectangle）+ 粗线条图形（36px 线宽），多尺寸存 ico，清晰锐利；前后台用不同图形与配色（白轨道 vs 金仪表盘）。
- 预防：Windows 图标 = 程序化绘制 > AI 位图；图形要粗线条、高对比、圆角卡片样式；键控透明阈值要处理抗锯齿软边。

### 22. Windows 图标缓存不刷新
- 现象：改了 .ico 后桌面还是旧图标。
- 解法：`ie4uinit.exe -show` 轻刷；不行就重启 explorer（taskkill /f /im explorer.exe && start explorer.exe）。
- 预防：设置图标后主动刷新并让用户确认。

### 23. 反复弹窗（搜狗 kmenureg / 守护常驻）
- 现象：桌面反复弹搜狗输入法菜单崩溃窗（kmenureg）、"守护常驻"bat 弹窗、cpolar 弹窗。
- 解法：找到对应进程/启动项禁用（.disabled 重命名、任务计划删除、启动项移除）。
- 预防：弹窗类问题优先查启动项（shell:startup）+ 计划任务。

## 四、流程与协作

### 24. 分工指令"转发制"
- 模式：前端（前端）/ 后端（后端）的指令由用户转发执行，我方只产出指令文本，不直接操作对方工作区；执行结果由用户带回，我方核查。
- 预防：指令要写清「验收标准」，用户可对照检查；不要假设对方已完成，先要反馈。

### 25. 评委视角测试法
- 模式：以评委/刁钻用户视角走全流程挑刺：文案不一致、承诺不符、404、兼容性、打包缺件、历史恢复。
- 预防：每次改版后按"文案一致性 → 档位承诺 → 异常路径 → 导出完整性 → 移动端"清单复检。

### 26. 演示视频录制教训
- 现象：计划录真实操作演示视频。
- 要点：bu 窄视口不适合录宽屏 → 用 cu 全屏；深度版生成 4-5 分钟等不起 → 用历史记录展示深度版结果；简洁版可真实生成（约40秒）；视频要等网站优化完再录，否则录旧版。

---

### 27. 数据/结构必须查证实测，禁止推断（血泪教训）
- 现象：拍板"评分五维=创新/技术/商业/落地/表达 30/30/20/10/10"，实际代码里是两套：创意评分（创新30/可行25/市场20/壁垒15/社会10）与评委评分（结构30/逻辑25/数据20/格式15/说服10），推断值全部错误。
- 根因：凭"看起来合理"推断系统结构，没有查代码。
- 解法：任何要对外拍板的数据、字段、权重、口径，先 SSH 拉实际代码/查官方来源实测，再下结论。
- 预防：涉及"五维/字段/权重/接口结构"一律先 grep 服务器代码；拿不准就明说"待查证"，不编。

### 28. 指令出口前自检（真实性/合理性/可实现性）
- 原则：给前端/后端/队友的任何指令，发出前先自问三点——① 事实是否查证过（数据/字段/接口现状）② 逻辑是否合理（有没有自相矛盾、承诺不符）③ 对方是否可实现（依赖现有代码还是新造轮子）。三者缺一先补查，不盲发。
- 场景：评分五维拍板（推断被证伪）、文案"50秒/40秒"承诺（与实际不符）、打包"已含PPT"（实际缺件）等。
- 预防：指令里涉及"现状/数据/承诺"的表述，全部以实测为准；每批指令发出前跑一遍这三问。

### 29. 导出 docx 中文乱码（????）
- 现象：tmp_export_single.docx（9-28 21:05 导出）文本节点全部 ????，文件 36KB 内容仅 14 字符。
- 根因：docx 生成时中文写入编码错误（非 UTF-8 正确写入字体/文本节点）。
- 解法：修正导出 docx 的中文编码写入；导出后用 python-docx 回读校验中文字符正常。
- 预防：导出链路加"中文回读校验"（检测 ???? 或乱码即拦截重导出）。

### 30. 导出 docx 无 TOC 目录
- 现象：用户"计划书目录没有"；计划书/申报书 docx 均无 TOC 目录域。
- 根因：导出渲染未插入基于 Heading1/2 的动态目录域。
- 解法：导出时插入 TOC \o "1-2" 域，基于真实 Heading 1/2 生成；目录可刷新。
- 预防：导出检测"是否有 TOC 域"作为必查项。

### 31. 申报书导出内容错位
- 现象："申报书.docx"里装的是"评审意见评分表"而非申报书正文。
- 根因：导出入口/参数把评审意见当申报书导出，或前端传错内容。
- 解法：按产物类型严格对应导出内容（申报书=正文、评审意见=评审反馈）。
- 预防：导出前校验内容与产物类型匹配（开头含"评审意见"即拦截）。

### 32. 生成任务被 reload 打断（闪退/生成失败）
- 现象：用户"后台卡顿闪退"；21:17 reload 时 worker 158372 退出前仍在跑深度生成，进行中请求断连。
- 根因：gunicorn reload 会杀掉在跑 worker；长任务（600s）未做断点续传/前端重连。
- 解法：reload 前等待在跑任务完成（或 graceful 阈值覆盖）；前端断线自动重连/恢复进度。
- 预防：部署/重启前检查是否有进行中生成；生成失败必须给出明确原因。

### 33. 生成内容引用过时预测数据
- 现象：计划书"预计2035年前后60岁+突破4亿"；官方口径（民政部副部长2026-03）为"2031年前后突破4亿"。
- 根因：知识库/提示词中预测值过时（或模型内部记忆），生成未校验时效。
- 解法：行业/统计类数据入库时标注"数据日期与口径"，生成前检索最新；对预测值二次核验。
- 预防：检测系统对"预测/测算值"强制校验数据日期；引用必须有可访问来源。

### 34. 深度版申报书内容偏薄
- 现象：300KB 深度版总字符仅 3404；应 7000-10000 字。
- 根因：内容生成章节覆盖不足或省略。
- 解法：深度版各章节写作指令加厚；导出后校验字数阈值（<6000 提示补全）。
- 预防：深度版字数下限检测（内容完整性一票）。

### 35. 结构化数据平铺段落未用表格
- 现象：申报书评分表（维度/权重/得分）用平铺段落，未用 Word 表格。
- 根因：导出渲染未把结构化数据转表格。
- 解法：评分/对比等结构化数据统一渲染为真实表格（含表头）。
- 预防：检测"应表格化的数据是否用表格"。

### 36. 图表 PNG 体积大
- 现象：generated 129 张图表 PNG 单张 81-246KB。
- 根因：图表渲染未压缩（分辨率/画布偏大）。
- 解法：PIL 压缩/降分辨率，目标 ≤60KB/张。
- 预防：导出体积检测（Word≤1.5MB、PPT≤2MB）。

### 37. 历史记录打开无图表/PPT（同 #11，确认未修复）
- 现象：用户"第二次深度生成没有图表 PPT也没生成"；生成端数据完整，但 /api/history/<id> 返回体不含 rich_deck/rich_charts/rich_tables → 历史打开富媒体区为空。
- 根因：历史恢复接口未返回富媒体字段（#11 已记录但未落地）。
- 解法：/api/history/<id> 返回体补富媒体字段；前端恢复渲染。
- 预防：历史恢复链路加"富媒体字段存在性"检测。

### 38. 首屏闪屏（深→白）
- 现象：首帧渲染深蓝紫(#0b1030)再切白底，视觉闪屏。
- 根因：<body> 无默认 light class，CSS 默认变量深色，JS 异步加 light。
- 解法：<body class="light"> 首帧即白底（已修复 v=20260928f）。
- 预防：视觉类改动部署前用 bu 验证首帧渲染。

### 39. 静态资源版本号未 bump → CF 缓存旧版（17:30 全站失效）
- 现象：17:30 全站 JS 不执行（COMP_TYPES 未定义），CF 边缘缓存了语法错误旧版 app.js。
- 根因：部署新版未 bump 版本号（仍 v=11），CF 缓存旧文件。
- 解法：静态资源改动用时间戳唯一版本号（v=20260928f）+ 备份 + 公网实测（部署铁律，105 轮）。
- 预防：每次前端改动必须 bump 时间戳版本号；部署后 bu 实测关键功能。

### 40. 后台反馈 10 条硬限制
- 现象：后台"最近 10 条反馈"（/api/feedback LIMIT 10），用户要求取消。
- 根因：接口硬编码 ORDER BY id DESC LIMIT 10。
- 解法：改分页参数（limit/offset）+ 返回 total（112 轮已派）。
- 预防：管理端列表接口默认支持分页，不做隐性截断。

### 41. 生成失败原因不透明
- 现象：用户"第二次不知道什么原因生成失败"——前端只显示"生成失败"无原因。
- 根因：失败原因未传前端展示。
- 解法：失败响应带原因（超时/繁忙/断网/中断），前端展示（115 轮已派）。
- 预防：失败必有原因字段，检测系统校验失败日志完整。

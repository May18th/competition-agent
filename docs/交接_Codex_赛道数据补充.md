# 交接：赛道 / 作品类别数据补充

## 背景

前端已支持「赛道选择」，但**只对知识库里真写了 `## 赛道设置` 的赛事生效**——
这是有意的：没有真实赛道数据就显示一个空选择器，等于让学生对着空气做选择，
还不如不显示。

目前 15 个知识库里**只有 `iCAN.txt` 有赛道**（创新 / 创业 / 挑战三赛道，你已补 `## 赛道设置` 块）。
其余 14 个一律不显示赛道选择，不是前端没做，是没数据。

## 前端怎么消费赛道（你补数据时的格式要求）

在 `data/xxx.txt` 里加一个块：

```
## 赛道设置
(1)创新赛道：双盲评审，侧重原创原型，不强制商业化；材料不能出现学校、导师信息。
(2)创业赛道：侧重商业落地、市场与盈利，适合已有订单试点项目。
(3)挑战赛道：企业联合命题专项赛道，含 AI 应用、机器人、电子信息等赛项。
```

解析规则（`scripts/build_comp_index.py :: parse_tracks`）：
- 块标题必须是 `## 赛道设置`（带括号后缀也认，如 `## 赛道设置（2026）`）
- 每行 `(n)名称：说明` —— **编号和冒号缺一不可**，否则该行被跳过
- `名称` 去掉「赛道」二字后作为 key；`说明` 作为官方原文 desc 原样展示

补完**必须重跑** `python scripts/build_comp_index.py`，否则前端拿不到
（前端读的是 `static/competition_index.json`，不是直接读 txt）。

## 建议优先补这三类（按价值排序）

### 1. 挑战杯（大挑）—— 作品类别，价值最高

`挑战杯.txt` 第 3 行只提了一句「提交学术论文、调查报告、科技发明作品」，
但**没有展开**。这三类作品的文档结构完全不同：

| 类别 | 结构差异 |
|---|---|
| 学术论文 | 摘要 / 方法论 / 实验设计 / 数据与分析 / 结论 / 参考文献 |
| 调查报告 | 调查对象与抽样 / 问卷或访谈设计 / 数据呈现 / 发现 / 建议 |
| 科技发明 | 技术方案 / 结构设计 / 测试数据 / 与现有方案对比 / 应用前景 |

现在不区分，三类都按同一个通用申报书骨架写 —— 学生交调查报告却拿到论文的
「实验设计」章节，结构就是错的。

建议加：
```
## 赛道设置
(1)学术论文类：侧重科研严谨性，需完整方法论与数据分析，附参考文献。
(2)调查报告类：侧重样本代表性与数据真实，需抽样方法、问卷/访谈设计、数据呈现。
(3)科技发明类：侧重技术方案可行性与实物验证，需结构/电路设计、测试数据、对比。
```

### 2. 计算机设计大赛 —— 已有线索但没展开

`计算机设计.txt` 第 3 行提到「分 11 大类，AI 应用赛道适合 AI 软件项目」。
11 大类是官方明确划分的（软件应用与开发、微课与教学辅助、物联网应用、
大数据应用、人工智能应用、信息可视化设计、数媒静态/动漫/游戏/微电影…），
如果有官方分类列表，值得补。

### 3. 互联网+ —— 赛道/组别

`互联网+.txt` 提到过赛道。互联网+ 官方分「高教主赛道 / 青年红色筑梦之旅赛道 /
职教赛道」等，各赛道评审要点差异明显（红旅赛道看重社会价值与乡村振兴）。
如果手上有官方材料，建议补。

### 不建议补的

- 数学建模、蓝桥杯、电子设计这类**命题型/评测型**赛事：评审看的是解题与测试
  结果，不存在赛道差异，补了也是凑数。
- 国创：`国创.txt` 目前 0 评分 0 章节（上次列的标题错位还没补），
  建议先补齐基础块，再谈类别。

## 一个约定

赛道数据**只写官方有的**。如果某个赛事的赛道划分是我们推断的，
要么不写，要么在说明里明确标「（推断，非官方）」——
学生照着填错赛道，比没有赛道选择更糟。

（前端对 focus/avoid/sections 这类推导内容已标 `derived: true`，
渲染时会跟官方 desc 区分开；但 `desc` 本身必须是官方原文。）

## 一、第二十轮派给 WorkBuddy 的 4 条：全部完成

### 1. 导出失败无重试 → ✅ 已修（新增 wbExportFetch）

- 所有导出请求（Word / PDF / 路演 PPT / 打包 zip / 原格式）统一走 `wbExportFetch()`：
  - 非 4xx 失败（网络异常、5xx）**自动重试 1 次**（间隔 900ms）
  - 4xx 直接返回不重试——内容/参数问题重试多少次都一样，白白浪费用户时间
- 仍失败走 `wbExportError()`：能取到后端 `error` 就照实说，取不到就给可行动文案
  「Word 没导出成功，服务正在重启或网络抖动 / 已自动重试过一次；页面内容和生成结果都还在，稍后再点一次即可，不用重新生成」
- 探针实测（接管 window.fetch 计数）：500 → 调用 2 次；网络异常 → 2 次；400 → 1 次 ✅

### 2. 步骤编号混乱 → ✅ 已修

- 根因：选填区块各自写死序号（补充规则「第 3 步」/ 补充信息「第 3 步」/ 草稿「第 3 步」/ 团队成员「第 2 步」），
  和真正的必填流程（赛事、创意）撞号
- 改法：**只有必填项编号**——「第 1 步 · 赛事名称」「第 2 步 · 项目创意」；
  四个选填区块去掉序号，只留分组名 + 「（选填）」
- 引导弹窗文案同步统一为「第 N 步」（原来是「第一步/第二步/第三步」，与表单阿拉伯数字不一致）
- 线上实测：「第 3 步」计数 0，「第 1 步」「第 2 步」各 1 ✅

### 3. 导出中心无 PPT 单文件下载 → ✅ 已修（根因与判断不同，说明一下）

- **不是没有入口**：入口一直在，但整行挂着 `deep-only`，简洁版整行 `display:none`，
  所以跑简洁版时用户根本看不到它，只在打包 zip 里见过 PPT
- **说明文案也误导**：写死「所有材料均为 Word(.docx) 格式」，与实际（另有 PDF、pptx）不符
- 改法：
  - PPT 行改为常驻显示，不再随档位隐藏
  - 说明文案改为「分项材料为 Word(.docx)，申报书另有 PDF，路演 PPT 为 .pptx（深度版）；可单独下载，也可一键打包」
  - 简洁版按钮自动变「深度版可用」+ 标签「（深度版）」，点了给带路径的引导
    （切深度版重跑一次即可，zip 里也有一份），而不是干巴巴一句「请先用深度版生成」
  - 打包按钮文案「一键打包下载全部 Word 材料」→「一键打包下载全部材料」（zip 里含 pptx，不只是 Word）
- 线上实测：PPT 行 display:flex、按钮「下载 PPT」、新文案在位 ✅

### 4. 简洁版文案校准 → ✅ 已修（按服务器真实统计，未直接采用「7800 字」口径）

  - 深度版：**约 4 分钟出 12000 字级完整方案书**（近 20 次实测 3.5~4 分钟）
- 「比你泡碗面还快」「刚好够你续杯咖啡」两个比喻全部清掉；meta/引导/档位卡片/深度版升级钩子

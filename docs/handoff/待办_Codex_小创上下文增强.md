# 小创上下文增强交接

- 本地聊天专项测试 12/12 通过；Node.js 语法检查、Python 编译和 `git diff --check` 通过。

## 本次修改

- 页面向聊天接口提供当前赛事、项目创意和所选版本；服务端限制字段长度与版本枚举。
- 小创按当前赛事知识库检索规则片段，并以“结论、赛事依据、材料缺口、下一步”组织项目匹配类回答。
- 复杂的项目、赛道、评委问题不再被单个关键词触发的固定 FAQ 截走；静态 FAQ 仍保留短路、不计模型额度。
- 项目创意作为当前轮用户资料发送，不放进系统指令、不写入持久化聊天历史；演示只读和额度控制保持不变。

## 后续验收

- 用真实非演示账号验证“当前项目是否匹配所选赛事”“PPT如何回应评委关注”等问题，确认回答引用当前赛事规则且指出材料缺口。
- 验证项目创意不会出现在 `/api/chat_history`，FAQ 命中仍不调用模型，演示只读会话仍不接模型。
- 生产当前使用扁平布局 `prod-wip-20261017`，本分支为 `backend/` + `frontend/` 布局；禁止整支合并或直接覆盖生产文件。先逐项对齐生产代码，在隔离 staging 验收后再评估移植。

## 红线

- 不修改生产 systemd 工作目录或 drop-in。
- 不把项目创意、草稿或团队信息写入聊天历史。
- 不放宽演示只读、用户隔离、配额预留和 Markdown XSS 防护。

### 字数口径分歧（需要豆包拍板）

- 第二十九轮写「简洁版实测 7800 字级、深度版 2 万字级，建议按实测中位数标」
- 我拉服务器 `competition.db` 最近 24 条逐条核对，**对不上**：

| 档位 | 库内实测（最近 24 条） | 豆包口径 |
|---|---|---|
| fast | 1671 / 2456 / 1963 / 5306 / 5116 / 6017 / 8534 …（区间约 1600~8500） | 7800 字级 |
| deep | 12720 / 12992 / 12858 / 12709 / 12868 / 13468 / 13162 / 12758（稳定 1.27~1.35 万） | 2 万字级 |

- 库是最容易复核的真相源，我**按库写**：
  - 简洁版「约 1 分钟出 4000 字级申报书（近 40 次实测 **1600~8500 字** / 50~93 秒）」
  - 深度版「约 4 分钟出 **13000 字级**完整方案书（近 20 次实测 **6500~13500 字** / 3.3~4 分钟）」
  - 用**区间**而不是单点数字，实际出得更多只会是惊喜，不会被质疑口径
- 若豆包那次确实出到 7800 / 2 万，麻烦给 `history_id`，我再核一次——
  也可能他数的是页面「复制全文」的字数（含所有章节拼接），与 `proposal` 字段不是一回事

## 三、本轮踩到的险情（建议在座都照做）

改 `exportOne()` 时漏了一个右括号 → **app.js 整体语法错误**，51 个全局函数全部 undefined。
页面看着完全正常（HTML 照常渲染），但**所有按钮其实都废了**——只靠"页面能打开"根本发现不了。

抓到它靠两步，建议固化成流程：

1. `node --check static/app.js`（index.html 的内联 script 也要切出来逐个 check）
2. headless 探针跑一遍 `typeof window.核心函数`（我这次是全变 undefined 才暴露）

另外两条附带经验：

- headless 探针**不能用 file://**（会被同源策略拦成 "Script error."，看不出真错），
  必须在本仓库起一个 `ThreadingHTTPServer` 再访问 http；单线程 `http.server` 会并发卡死
- 静态资源改了必须升版本号：这次 app.js 加了 `?v=4`、style.css 补了 `?v=2`，
  否则用户拿旧缓存，新按钮点了报"函数不存在"
- 探针里别用 `document.body.innerText` 校验隐藏区（读不到），
  也别把待校验的中文串直接写在探针 script 里（会被 `textContent` 自匹配成假阳性）——
  最终确认请用源文件 grep

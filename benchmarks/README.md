# 评测基准

用来回答一个问题：**这个系统写出来的申报书，凭什么比直接用通用大模型写得好？**

答案不能是观点，得是同一批题目、同一套打分口径下的对照数据。

## 三组对照

| 组 | 含义 | 怎么跑 |
|---|---|---|
| `baseline` | 通用大模型裸写。只给赛事名 + 那一句创意，要求写一份可提交的申报书。不给赛事规则、不给范文、不做质检 | 直调模型 |
| `fast` | 本系统简洁版 | 真实生产接口 `/api/generate_async`（mode=fast） |
| `deep` | 本系统深度版 | 同一接口（mode=deep） |

题目集在 `cases.json`：20 题覆盖 15 个赛事，每题只给一句话创意——与实际用户输入的信息量对齐，三组拿到的输入完全一样。

## 尺子（主证据 + 四条辅助）

1. **人工盲评（主证据）**
   `blind/` 下每题有三份匿名正文（A/B/C）和 `blind_scores.csv` 打分表。按该赛事**官方评分维度**逐项 1–10 分（维度与权重来自 `competition_profiles.json`），填总分。
   映射表在 `blind/<case>_map.json`，评分前不要打开。
   至少 3 人独立打分取均值，评分人不知道哪份是系统出的。

2. **导出质检机器分 · 生产口径（辅助）**
   用系统自己的 `score_export` 给三组同规则打分，衡量的是「有没有硬伤」（空文档/乱码/占位符/双盲泄露/缺章节），**命中一票否决就是 0 分**，代表「能不能直接交付」。不衡量文采，不能单独当结论。

3. **导出质检机器分 · 评测口径（横向对照用）**
   同一条规则，但否决原因只记录不归零。原因是裸写组从未被要求规避双盲信息，只报生产口径会让它整列 0 分，对照没有区分度。报告的「平均机器分(评测口径)」用这一列。

4. **官方维度自查分（辅助）**
   按该赛事官方评分维度逐项核对（与产品内「评分项自查」同一套判据），看得出「创新点有没有集中列出 / 有没有量化数字 / 有没有对标」。同样带系统侧偏向，不单独当结论。

5. **质量门警告项**
   逐题记录触发的警告（缺图表、套话、字数不达标等），反映交付前的返工量。

> 实测：机器分对三组几乎没有区分度（c01/c02 三组同为 92），唯一拉开差距的是双盲否决项；真正能区分内容质量的是「官方维度自查分」。这也是为什么主证据必须落在人工盲评上。

## 跑法

```bash
# 服务端（配额要放宽，20 题三组约 800 次模型调用）
QUOTA_DAILY_LIMIT=5000 python -u -c "from app import app; app.run(host='127.0.0.1', port=8080, use_reloader=False)"

# 试点：3 题三组，约 20 分钟
QUOTA_DAILY_LIMIT=5000 python benchmarks/run_benchmark.py --limit 3

# 全量：20 题三组，约 2.5 小时
QUOTA_DAILY_LIMIT=5000 python benchmarks/run_benchmark.py

# 断点续跑：已跑过的题会自动跳过，中断后重跑同一条命令即可
# 只对已有结果重新打分（不重新生成）
python benchmarks/run_benchmark.py --score-only benchmarks/runs/20261124-203133
```

产物落在 `benchmarks/runs/<时间戳>/`：逐题正文与 meta、`summary.csv`、`report.md`、`blind/` 盲评包。

## 读数时要注意

- **样本量**：3 题只能验证管线，不能下结论；对外引用至少要跑满 20 题。
- **机器分同源偏差**：机器分用的是本系统自己的规则，对系统侧天然有偏向，所以主证据必须是人工盲评。
- **baseline 的公平性**：裸写组只拿一句话，这确实比真实使用场景苛刻（真实用户会反复追问）。如果要把结论说成「比通用模型强」，得在报告里写明这个前提；更稳妥的表述是「在只给一句话输入的条件下」。
- 每题只跑一次，模型有随机性；要谈稳定性，同一题需重复 3 次看波动。
- **成本**：20 题 × 4 组约 5.5M tokens（单份 deep 158k、fast 68k）。改一处提示词就想验证效果时，**只重跑受影响的那一组、且限 3～5 题**，别全量重来。

## 已经试过、证明无效的方向（别重复踩）

| 改动 | 结论 |
|---|---|
| 给简洁版加字数下限（1600～1800 + 每章下限） | **无效**。13 题配对自查分 73.9 → 69.7（-4.2，胜 2/13），字数也没涨（1967 → 1821）。「写长」不等于「覆盖评分点」，硬凑会打乱结构。产物留档在 `runs/20261125-132240/`（含 NOTE.md） |

## 已知口径缺陷

- `可视化资产` 一项只读正文，深度版的图表/表格/PPT 不在正文里，对 deep 系统性扣约 3.5 分。要比含媒体的精确分，走 `/api/scorecard` 传完整 result_data。
- 各组分题数不等时（中途中断），报告里的分组均值不可横比——先看逐题明细里三组都齐的题号。
